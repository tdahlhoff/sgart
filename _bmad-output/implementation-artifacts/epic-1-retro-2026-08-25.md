## 3. What Repeated — Challenges

### 3.1 The `commandId` idempotency footgun — the dominant recurring bug
Same root cause surfaced in **three** stories, caught in review every time, never in dev:

- **1.6** — retries created *duplicate* households (idempotency keyed on `(user, householdId)`
  instead of `(user, commandId)`; client minted a fresh id per call).
- **1.7** — an edited rename after a lost response reused the `commandId`; `EventStore.append`
  deduped it as a silent no-op success, so the client showed "C" while the server kept "B".
- **1.8** — the second store added in one screen session silently vanished: a *spent*
  `commandId` was reused after success.

The "commandId dedup = silent no-op" contract is subtle and the client kept misapplying it —
reusing an id across semantically different intents, or failing to regenerate after success.
**This is the single most important thing to fix before Epic 2, which is nothing but rapid
list/item writes.**

### 3.2 Fail-fast HTTP error-mapping gaps
Malformed / missing input returned HTTP 500 instead of a mapped 4xx in **1.6, 1.7, and 1.8** —
each new command path re-learned that its error advice + test was incomplete.

### 3.3 Accessibility & Boy-Scout cleanup landing in review, not build
Dead switcher tooltip string (1.7), dead `error` field (1.8), missing semantics label (1.7),
stale doc comment (1.11), UTF-16 avatar-initial split (1.11). Low severity, but a consistent
"caught in review, should have been built in" pattern.

### 3.4 "Premature value" — stories/sub-features ahead of their enabling capability
Raised by the Project Lead. Surfaces whose real value depends on a *later* epic:

| Story | Surface | Blocking capability |
|---|---|---|
| 1.9 | „Schritt 3 von 3" invite step (inert) | Invites — Epic 4 |
| 1.11 | Notifications info block (static, no toggle) | Content-free push — Epic 4 |
| 1.9 / 1.6 | „Auf Einladung warten" choice (dead-end) | Invites — Epic 4 |
| 1.10 | Locale/region selector (thin) | Second language — post-MVP by design |

**Assessment:** the *epics* are well-sequenced (each solo-capable, building on the prior;
Epic 4 is exactly where the inert placeholders get completed). No epic reorder is warranted.
The lesson is a **story-authoring rule**, applied at `create-story` time (see Action 4).

### 3.5 Process felt heavy
The clarify → dev → review → fix loop per story is thorough but heavy. Notably, much of the
review churn was the *same* recurring bug classes (§3.1–3.3) resurfacing. Fixing those at the
root (Actions 1–3) should directly lighten the per-story loop.

## 4. Action Items (carried into Epic 2)

**Root-cause fixes — these also lighten the "heavy" loop:**

1. **Extract a client command-id abstraction.** One `commandId` per intent; regenerate on
   payload change and after a successful append. A single reusable helper used by every write
   cubit, with tests proving edited-retry and post-success both regenerate.
   *Owner: Dev · Before Epic 2's first write · Directly kills §3.1.*

2. **Base error-advice contract test.** Assert every command endpoint maps missing/malformed
   input and every reachable domain exception to a 4xx — never a 500.
   *Owner: Dev · With Epic 2's first write path · Kills §3.2.*

3. **Extend the story Definition-of-Done checklist:** commandId lifecycle correct · error advice
   mapped + tested · a11y labels on new interactive widgets · no dead strings/fields/stale
   comments · client fail-fast guard on text inputs.
   *Owner: Process · From Epic 2 story 1 · Front-loads §3.3 so it's built-in, not review-caught.*

**Sequencing / value (Project Lead's insight):**

4. **Adopt the premature-value story-authoring rule.** At `create-story` time, sanity-check each
   remaining story: don't author a surface whose value depends on a later-epic capability — move
   it to that epic, or ship it as an *explicit minimal placeholder*. Right-size thin,
   MVP-scoped stories rather than over-building.
   *Owner: PM / create-story · From the next story onward.*

5. **No epic reorder; verify pickup instead.** Keep the current epic order. Ensure Epic 4 stories
   explicitly *complete* the Epic 1 placeholders (invite step, notifications toggle, „Auf
   Einladung warten" flow). Accept 1.10 as-is (region formatting has marginal value; full
   language value is post-MVP).
   *Owner: PM · Note on Epic 4 planning.*

**Operational:**

6. **One real end-to-end stack run before/early in Epic 2.** Everything to date is
   Testcontainers/unit-verified; the full interactive stack (needs `SGART_FLYWAY_ENABLED=true`
   *and* `SGART_PROJECTOR_AUTOSTART=true`) has never been run end-to-end. Epic 2 ships the first
   genuinely interactive user surface — a real run-through is prudent. Not a blocker.
   *Owner: Dev.*
