## 2. What Went Well

- **Model-first planning worked — the epic's headline win.** `epic-4-membership-state-model.md` was
  drafted up front as the single ubiquitous vocabulary for 4.1–4.6. No membership-vocabulary re-churn
  occurred across the epic; 4.4/4.5/4.6 each consumed the model with "no new membership state." This
  is the direct, successful application of Epic 3's Action 1.
- **The task↔test manifest held.** Every story carried a Test Manifest, and the 4.6 acceptance
  auditor confirmed **zero** `[x]`-task-without-test integrity failures — Epic 3's dominant defect
  (§3.2) did not recur.
- **"Code the testable seam now, document prod-infra" matured into a repeatable pattern** (4.5 push,
  4.6 Keycloak Admin lookup + web fallback): config-gated adapters default-off, so CI/local dev need
  no external credentials, and the production wiring is captured in `docs/first-real-world-test.md`.
- **DRY held under pressure.** Two invite entry points (OS deep link + web fallback) both reuse
  Story 4.2's single `AcceptInvite` path; the 4.6 review confirmed no second accept code path.
- **Fix-commit rigor held** (Epic 3 Action 4): the 4.6 review-fix pass added tests exercising the
  exact branch each fix claims (config.json endpoint, plus-addressed email, no-dev-logging no-build)
  and corrected stale javadoc (T3), rather than rubber-stamping.

## 3. What Repeated / Hurt

### 3.1 Foundational technical decisions surfaced in code review, not planning (headline)
Story 4.4's SSE fan-out was implemented **blocking** first and took **two code-review rounds** to
correct to a non-blocking model. Blocking-vs-non-blocking is an architecture/transport decision that
belongs in the story's technical-approach plan; code review is an expensive and late place to catch a
foundational implementation-approach mistake.

### 3.2 Test-coverage gaps in exactly the risky places
- **SSE fan-out paths** (4.4) were under-tested — part of why the blocking model slipped through to
  review. The fan-out shutdown race is now in `deferred-work.md` (shared with the 4.5 fan-out).
- **GDPR erasure/export paths** lack first-class tests, despite Epic 4 being the first PII epic and
  CLAUDE.md §6 requiring right-to-erasure / export / retention to have their own tests.

### 3.3 Checkpointing debt was deferred again
Epic 3 Action 6 explicitly asked to resolve `fromStart`-replay-on-every-reconnect projectors
before/early in 4.4, since it becomes multi-user-visible under SSE. It shipped as standing debt
instead. Still open; carried forward.

## 5. Next Epic Preview — Epic 5: Offline Resilience & Conflict

Offline queue with a visible pending count → idempotent replay & silent convergence → coarse
conflict detection (keep-mine / discard) (FR8). Per `epics.md`, Epic 5 is **"purely client-side + a
conflict UI, touching no existing handler"** — every command already carries the
`commandId`/`basedOnVersion` envelope (AD-8), so server-side dependencies on Epic 4 are light.

**Primary risk:** Epic 5 is Flutter-heavy (queue/replay/conflict UI) — exactly the area §3.2 flags as
thin on coverage. The checkpointing debt (§3.3) also touches reconnect, which is Epic 5's territory.

**Epic 6 dependency:** Export & Erasure (FR14) is where the deferred GDPR feature tests and ADR-0001
crypto-shredding land. The Epic-4 privacy *mechanisms* (de-link = erasure, no-PII events, side-store
purge points) are testable now; the full export/erasure *features* belong to Epic 6.
