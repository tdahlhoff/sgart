SGART — a privacy-first household grocery & receipt tracker

One shared, live shopping list for a household — that quietly grows into a private record of what things cost where. Built domain-first, event-sourced, and self-hosted in Germany so grocery habits never touch a US cloud.

01

Four bounded contexts, one deployable

Contexts are code modules in a single Spring Boot application — never separate services. Each talks to another only through a published port or an async domain event, never by reaching into another's model or tables. For the MVP, the whole shopping experience lives in one core context.

02

How state changes — one way, always

Every change is a command handled by an aggregate that appends events under an optimistic-concurrency check. Read models are projected from those events and are never written directly — so there is exactly one source of truth, and reads can lag writes without ever contradicting them.

03

Identity & the right to be forgotten

Event sourcing keeps an immutable log; DSGVO demands erasure. SGART reconciles them by keeping no personal data in the log at all. Events reference a person only by a household-scoped pseudonym; one small mapping table is the sole link back to a real identity, and erasing it leaves the history intact but anonymous.

04

Offline edits, honest conflicts

Shopping happens in stores with bad signal. Actions queue locally and replay on reconnect. The same expected-version check that guards every write also detects offline conflicts — so the MVP surfaces a genuine conflict for a simple choice instead of silently overwriting, and never needs a merge engine.

Decision ledger

The eleven invariants a future builder can't read off the code. Each fixes one way two independently-built units could otherwise diverge.
